Bring the stack up in layers
These are teaching stages, not commands run on a host. Physical provisioning uses the BCM-style image model. Kubernetes registration, GPU resource advertisement and PVC readiness are additional gates.
Research volume
A bound PVC does not prove that the storage data path is healthy. An existing mount can keep working through a CSI-controller outage while a new Pod waits to mount.

  
Submit and investigate training work
Distributed workers require different nodes in this reference plan. GPU IDs are exclusive; MIG, fractional GPUs and time slicing are outside this lab. Native mode can hold a partial group; Run:ai mode waits for a complete placement.
Worker Pod placement

  
Deserved quota, borrowing and reclamation
This two-project, single-pool policy is a teaching approximation. Priority is compared within a project; it is not a global right to evict another project's protected workload. Deserved quotas cannot oversubscribe physical capacity in this model. Application checkpoints are stored by the modeled training program, not by saving GPU memory.

  
Find the layer that stopped progress
API or kubelet loss does not automatically stop an existing application container. A missing device plugin blocks fresh GPU placement. RDMA or assigned-device failure can abort a running collective. Storage loss can leave a workload Running while it waits at required I/O.

  
Build evidence before changing a setting
Investigation sequence
  1. Complete setup and submit a small validation workload.
  2. Start one exercise and inspect its broken layer through the console or layer summary.
  3. Repair that dependency or policy. Failed jobs need an explicit restart.
  4. Submit a new validation workload and wait for final output publication.
For quota and PDB exercises, first finish or cancel other work. Quota starts a full-cluster preemptible borrower: let it run, inspect it, then submit an eight-GPU beta workload to reclaim deserved resources. The PDB exercise creates protected training: find its actual worker node, drain it, inspect the budget, then deliberately lower the budget or finish/cancel the workload before retrying maintenance.
